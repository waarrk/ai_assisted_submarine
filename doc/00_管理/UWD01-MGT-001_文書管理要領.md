# 適用範囲

水中ドローン UWD-01 の設計・開発で作成する文書と記録の，識別，保管，改訂，発行の方法を定める．

管理の考え方は ISO 9001:2015 の箇条 7.5「文書化した情報」と箇条 8.3「製品及びサービスの設計・開発」に沿う．箇条の対応は記憶に基づいており，規格の原本とは照合していない．

# 文書番号

文書番号は，文書管理台帳に登録した後に使用する．形式は「UWD01-種別-連番」とし，連番は種別ごとの 3桁とする．

表: 文書の種別 {#tbl:kind}

| 種別 | 対象 | 保管フォルダ |
|---|---|---|
| MGT | 管理要領，文書管理台帳 | 00_管理 |
| PLN | 設計開発計画書 | 01_計画 |
| REQ | 要求仕様書 | 02_要求 |
| DDS | 詳細設計書 | 03_設計 |
| CAL | 計算書，検討書 | 03_設計/計算書 |
| DRR | 設計審査記録 | 04_審査 |
| VER | 設計検証記録 | 05_検証 |
| VAL | 妥当性確認の計画書と記録 | 06_妥当性確認 |
| ECN | 設計変更記録 | 07_変更 |
| BOM | 部品表 | 08_購買/部品表 |

番号は再利用しない．廃止した文書は台帳の状態を「廃止」とし，行を残す．

# フォルダ構成

フォルダは設計・開発の段階ごとに分ける．各段階と ISO 9001:2015 の箇条の対応を @tbl:folder に示す．

| フォルダ | 段階 | 区分 | 対応する箇条 |

| 00_管理 | 文書と記録の管理 | 文書 | 7.5 |
| 01_計画 | 設計・開発の計画 | 文書 | 8.3.2 |
| 02_要求 | 設計・開発へのインプット | 文書 | 8.3.3 |
| 03_設計 | 設計・開発からのアウトプット | 文書 | 8.3.5 |
| 04_審査 | 設計審査 | 記録 | 8.3.4 |
| 05_検証 | 設計検証 | 記録 | 8.3.4 |
| 06_妥当性確認 | 妥当性確認 | 記録 | 8.3.4 |
| 07_変更 | 設計・開発の変更 | 記録 | 8.3.6 |
| 08_購買 | 外部から提供される製品の管理 | 記録 | 8.4 |

3次元モデルは cad フォルダ，設計値と計算は analysis フォルダ，見積の取得記録は quote フォルダに置く．これらは設計・開発からのアウトプットの一部として同じ版で管理する．

# 版と改訂

版は英字 1文字とし，初版を A とする．改訂のたびに B，C と進める．改訂の内容は表紙の改訂履歴に 1行で記載する．

発行済みの版は書き換えない．内容を変える場合は版を進め，前の版の提出物を 09_提出 に残す．

表: 文書の状態 {#tbl:status}

| 状態 | 意味 |
|---|---|
| 未作成 | 番号のみ登録 |
| 作成中 | 原稿を作成中 |
| 審査前 | 提出物を生成済み，承認者が未記入 |
| 発行 | 承認者を記入して生成済み |
| 様式未適用 | 内容はあるが本要領の様式に未移行 |
| 生成物 | 3次元モデルと計算から自動で生成 |
| 廃止 | 使用を中止 |

# 作成と発行

文書は原稿から提出物を生成して発行する．手順は次のとおりとする．

1. 文書管理台帳への文書番号と名称の登録
2. 原稿の作成
3. 日本語の機械検査での検出 0件の確認
4. 提出物の生成
5. 提出物の目視確認
6. 審査者と承認者の記入と再生成

提出物の生成時に，原稿の文書番号，名称，版を文書管理台帳と照合する．一致しない場合は生成を中止する．生成後は台帳の版，発行日，状態，提出物の場所を自動で更新する．

表紙には文書番号，版，発行日，機密区分，作成・審査・承認，改訂履歴を記載する．全ページのヘッダに文書番号と版を記載する．

# 記録の保持

審査，検証，妥当性確認，変更，購買の記録は，作成後に書き換えない．訂正が必要な場合は，訂正の内容と日付を追記する．

3次元モデルの生成結果のうち，質量，干渉，拘束の出力は設計検証記録の根拠として保持する．
